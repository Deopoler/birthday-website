# 하진 순장님 생일 축하 사이트 🎂

봉투를 열면 밤하늘에 '하진' 모양 별자리가 나타나고, 별을 누르면 친구들의 롤링페이퍼 편지가 열려요. 아래로 내리면 포스트잇 사진판이 나와요. 휴대폰 화면에 맞춰 만들었어요.

- 주소: https://deopoler.github.io/birthday-website/

## 한눈에 보기: 저장소가 두 개예요

| 저장소 | 공개 여부 | 들어 있는 것 |
|---|---|---|
| `Deopoler/birthday-website` (여기) | **공개** | 사이트 코드만. 사진·메시지는 없어요 |
| `Deopoler/birthday-content` | **비공개** | 사진(`photos/`)과 메시지(`messages.json`) |

- 내 컴퓨터에서는 비공개 저장소가 이 폴더 안의 **`content/`** 폴더로 들어가요. `content/` 는 공개 저장소에 올라가지 않아요.
- 사이트를 배포할 때 GitHub Actions 가 비공개 저장소를 가져와서, **크기를 줄인 사진 사본**과 메시지를 사이트에 넣어요.

> [!IMPORTANT]
> 비공개인 것은 **저장소**(원본 사진·메시지 파일과 그 기록)예요. 생일 당일에 배포된 사이트의 사진과 메시지는 주소를 아는 사람 누구나 볼 수 있었어요. **생일이 끝난 뒤(2026-11-24 00:00 KST부터)는 비밀번호를 아는 사람만 볼 수 있게 잠가서 배포해요**(8번 참고).

## 1. 처음 한 번만

1. [Node.js](https://nodejs.org)와 [GitHub CLI](https://cli.github.com)를 설치하고, 터미널에서 `gh auth login` 으로 로그인해요.
2. 이 폴더에서 `npm install` 을 실행해요. (사진 보호 장치도 이때 켜져요. 6번 참고)
3. `npm run content:init` 을 실행하면 비공개 저장소가 `content/` 로 받아져요.
   - 이미 있으면 "이미 있어요"라고만 알려 줘요.
   - 커밋 이메일을 GitHub 비공개 주소(`…@users.noreply.github.com`)로 맞춰 줘요.
   - 미리 확인만 하려면: `npm run content:init -- --dry-run`

## 2. 사진 넣기 — `content/photos/`

- **`content/photos/` 폴더에 사진 파일을 넣기만** 하면 돼요. 휴대폰 원본 그대로 넣어도 괜찮아요.
  - 사이트에는 자동으로 줄인 사본(긴 변 1200px, 미리보기 640px, WebP)만 올라가고, **찍은 장소(GPS) 같은 정보는 지워져요.** 원본은 비공개 저장소에만 있어요.
- 화면에 나오는 순서는 **파일 이름 순서**(1, 2, 10 순)예요. 원하는 순서가 있으면 `01_바다.jpg`, `02_카페.jpg` 처럼 앞에 숫자를 붙여요.
- 형식: `JPG`, `PNG`, `WebP`, `AVIF`, `GIF`(첫 장면). ⚠️ 아이폰 **HEIC(`.heic`)** 는 못 읽을 수 있어요. 윈도우 '사진' 앱에서 열어 JPG로 저장해 넣어 주세요.
- 개수 제한은 없지만 **6~20장**을 권장해요. 사진이 하나도 없으면 색깔 더미 12장이 보여요.

## 3. 메시지 넣기 — `content/messages.json`

메모장 등으로 `content/messages.json` 을 만들고 아래 모양으로 써요. 순서대로 별 하나에 메시지 하나씩 붙어요.

```json
[
  { "from": "민수", "text": "순장님, 생일 축하드려요! 항상 감사해요." },
  { "from": "지연", "text": "오늘 하루 제일 행복하세요 🎂" }
]
```

- `from` 은 보내는 사람(최대 40자), `text` 는 편지 내용(최대 1000자). 둘 다 비어 있으면 안 돼요.
- 마지막 항목 뒤에는 쉼표(`,`)를 쓰지 않아요. 글 안에 큰따옴표를 쓰려면 `\"` 로 써요. 줄을 바꿔 써도 화면에서는 한 칸 띄어쓰기로 보여요.
- 편지 카드 크기가 정해져 있어 아주 긴 글은 잘릴 수 있어요. `npm run dev` 로 꼭 확인하세요.

**메시지는 정확히 17개**로 맞추세요. '하진' 모양 별이 17개예요.

- 17개보다 적으면: 메시지 수만큼만 별이 켜져요. 나머지 자리는 비고 글씨 획 일부가 완성되지 않으며, 카운터가 `★ 0 / 12` 처럼 그 개수로 보여요.
- 17개보다 많으면: 18번째부터는 화면에 나오지 않아요(빌드할 때 경고가 나와요).
- 파일이 없거나 `[]` 처럼 비어 있으면: 더미 메시지 17개가 보여요.
- 형식이 틀리면 미리 보기 화면과 빌드에 `content/messages.json:5:3 JSON 형식 오류 …` 처럼 **몇 번째 줄인지** 나와요. 고치고 저장하면 다시 떠요.

## 4. 내 컴퓨터에서 미리 보기

`npm run dev` → 터미널에 나온 주소를 열어요. 켜 둔 채로 사진을 넣거나 빼고 `messages.json` 을 고치면 화면이 바로 다시 그려져요.

## 5. 사이트에 반영하기

```bash
npm run content:publish
```

- `content/` 의 바뀐 내용을 비공개 저장소에 올리고(커밋 메시지는 `content: update 2026-11-20 14:30` 처럼 자동), 사이트 배포를 시작한 뒤 끝날 때까지 보여 줘요. **1~2분** 걸려요.
- 올리기 전에 `messages.json` 형식을 먼저 검사해요. 틀리면 아무것도 올리지 않고 어디가 틀렸는지 알려 줘요.
- 바뀐 것이 없으면 알려 주기만 해요. 하려는 일만 미리 보려면: `npm run content:publish -- --dry-run`
- 배포가 실패해도 사이트는 **이전 상태 그대로** 남아 있어요. 안내에 나온 주소에서 이유를 확인하세요.
- 사이트 코드(공개 저장소)를 고쳐 `main` 에 push 해도 자동으로 배포되고, 이때도 비공개 저장소의 사진·메시지를 가져와 넣어요.

## 6. 공개 저장소에 사진이 올라가지 않게 막는 장치

이 저장소는 공개라서 한 번 올라간 사진은 기록에 남아요. 그래서 두 겹으로 막아요.

1. **커밋할 때**(git 훅 `.githooks/pre-commit`): 커밋하려는 파일 중 이미지가 있으면 커밋을 막아요. `npm install` 때 자동으로 켜져요(이미 다른 훅 설정이 있으면 바꾸지 않고 경고만 해요).
2. **빌드·배포할 때**: `npm run build` 와 GitHub Actions 가 저장소 전체를 다시 검사해요. 훅을 건너뛴 커밋(`git commit --no-verify`)도 여기서 걸려 배포되지 않아요.

- 확장자를 바꾼 이미지, 하위 폴더의 이미지, 대문자 확장자(`.JPG`)도 잡아요.
- 검사를 할 수 없으면(예: node 가 없음, 오류) **통과시키지 않고 막아요.**
- 사이트 디자인용 그림(배경, 공유 이미지, 아이콘)만 [`scripts/allowed-images.txt`](scripts/allowed-images.txt)에 적혀 있어 통과해요.

**막혔을 때**는 화면 안내대로 하면 돼요.

- 실수로 넣은 사진이면 커밋에서 빼요(파일은 그대로 남아요): `git restore --staged -- "파일 경로"` → 사진은 `content/photos/` 로 옮겨요.
- 공개해도 되는 디자인용 그림이면 `scripts/allowed-images.txt` 에 그 경로를 한 줄 추가해서 같이 커밋해요.
- 이미 GitHub 에 push 된 사진이면 기록에서 지우는 작업이 따로 필요해요. 바로 알려 주세요.

**배포할 때 사진·메시지를 가져오는 규칙**(GitHub Actions, `.github/workflows/deploy.yml`):

- 공개 저장소의 Secret `CONTENT_DEPLOY_KEY`(비공개 저장소 읽기 전용 키)가 **없으면**: 경고를 남기고 더미 사진·메시지로 배포해요.
- 키가 **있는데 가져오기에 실패하면**: 배포를 멈춰요. 이미 올라가 있는 사이트가 더미로 덮이지 않게 하려는 거예요.

## 7. 링크 공유 미리보기·출처

- 카카오톡 등에 링크를 보냈을 때 뜨는 제목·설명은 `index.html` 의 `<meta>` 태그(`og:title`, `og:description`, `description`)에서, 이미지는 `public/og-image.jpg`(1200x630, 300KB 이하 권장)에서 바꿔요. 같은 이름으로 바꾸면 그대로 통과하고, 다른 이름의 이미지를 쓰려면 `scripts/allowed-images.txt` 에도 적어 주세요. 바꾼 뒤에도 카카오톡은 예전 미리보기를 기억하니 [카카오 공유 디버거](https://developers.kakao.com/tool/clear/og)에서 캐시를 초기화하세요.
- 탭 아이콘은 `public/favicon.svg`, `public/apple-touch-icon.png`.
- 이미지·글꼴 출처는 [CREDITS.md](CREDITS.md).

## 8. 공개 일정과 생일 이후 잠금

배포할 때마다 GitHub Actions(`.github/workflows/deploy.yml`)가 시각을 보고 무엇을 올릴지 정해요.

| 시각(KST) | 배포되는 것 |
|---|---|
| 2026-11-23 19:30 전 | 더미 사진·메시지(비공개 저장소를 가져오지 않음) |
| 2026-11-23 19:30 ~ 24:00 | 실제 사진·메시지 |
| 2026-11-24 00:00 이후 | **비밀번호 잠금 사이트**. 잠금용 Secret 이 없으면 사진·메시지 없는 '끝났어요' 안내 페이지(`scripts/ended/index.html`)만 |

- 19:30 공개는 `scheduled-release.yml` 이 예약 실행하게 해 두었지만 GitHub 예약 실행은 시각을 보장하지 않아요. 이미 지난 일정이에요.
- 잠금 사이트는 사진·메시지를 **암호화해서** 올려요. 비밀번호를 넣어야 이 기기에서 풀려 보여요(서버 없이 브라우저 안에서 풀어요). 잠금 빌드에서 암호화되지 않은 사진이나 소스맵이 남으면 배포를 멈춰요.

**잠금에 쓰는 Secret**(공개 저장소 Settings → Secrets, 값은 어디에도 출력하지 않아요)

| Secret | 뜻 |
|---|---|
| `SITE_CONTENT_KEY` | 콘텐츠를 암호화하는 무작위 키(32바이트 base64) |
| `SITE_PASSWORD` | 처음 비밀번호 |
| `SITE_LOCK_CODE` | 비밀번호를 바꾼 뒤 받은 `HJ2.` 잠금 코드. 있으면 `SITE_PASSWORD` 대신 이걸 써요 |

**비밀번호 바꾸기(한 번)**

1. 처음 비밀번호로 들어오면 새 비밀번호(8자 이상, 처음 것과 다르게)를 정하는 화면이 나와요. 정하면 `HJ2.` 로 시작하는 잠금 코드가 나와요.
2. 이 코드를 `gh secret set SITE_LOCK_CODE` 로 등록하고 `gh workflow run deploy.yml --ref main` 으로 다시 배포해요.
3. 그러면 모든 콘텐츠가 새 키로 다시 암호화되어 **새 비밀번호만 통하고 처음 비밀번호는 더 이상 쓸 수 없어요.** 코드가 `SITE_CONTENT_KEY` 와 맞지 않으면 빌드가 실패하고 이전 사이트가 그대로 남아요.
